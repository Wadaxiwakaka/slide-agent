# M1：AI Presentation Planner 规格

## 目标与边界

让本机单用户从网页输入主题或原始文本，指定受众、目的和页数，选择已配置的模型，生成可编辑 PPTX。AI 只负责内容与五种现有布局的选择；输出必须先变成有效的 DeckSpec，再交给 M0 的确定性布局与渲染链。M0 的示例下载继续可用。

M1 **不是公开部署版本**：没有登录、注册、管理员权限或多人隔离。开发和启动脚本默认只监听 `127.0.0.1`；公开部署前必须另行设计身份认证、配置存储、访问控制、额度限制和网络请求安全策略，不允许直接将此版本绑定公网。

## 用户行为

- 首页提供生成表单：主题或原始文本（至少填一项，也可两项）、受众、演示目的、目标页数（1–10）、当前模型配置。受众和目的有可编辑默认值；输入长度有上限（主题 200 字符、原始文本 20,000 字符、受众和目的各 120 字符）。
- 模型配置面板可新增、编辑、删除、选择当前配置，显示协议、名称、Base URL、模型 ID、密钥别名及“已配置/未配置”，并提供连接测试。测试连接可能产生少量模型费用，UI 应提示。
- 生成成功即下载 PPTX，页数等于请求页数；第一页为 `title`，后续页面由 Planner 从 M0 五种布局中选择。仅用原生可编辑文本和形状，不生成图片或坐标。
- 无可用模型、环境变量缺失、连接失败、超时、模型返回无效结构或排版校验失败时，显示可操作的错误提示，不下载损坏文件；界面、响应及日志不包含密钥或模型原始敏感请求头。

## 模型接入

- 支持三种协议：OpenAI 兼容、Anthropic 原生、Gemini 原生。第三方模型通过选择其中一种协议、填写符合该协议的 Base URL 和模型 ID 接入；M1 不支持上传模型权重或任意自定义 HTTP 报文格式。
- 同一 Planner 生成与协议无关的 DeckSpec；各协议只负责发送请求、提取文本、处理其错误。使用服务端请求，不将密钥交给浏览器；不做模型自动路由或模型间故障切换。
- 输出用 `deckSchema` 验证，并检查实际页数。模型返回不合法 JSON 或无效 DeckSpec 时可对同一模型重试**一次**；仍不合法则失败，并说明可能消耗两次调用。不得为了容纳坏输出而让 AI 提供 x/y/w/h 或修改 DeckSpec 核心模型。
- 单次网络调用最多等待 90 秒，模型响应正文最多接收 256 KiB；不跟随 HTTP 重定向。测试和生成都不得静默切换到其他配置。

## 配置与密钥

- 普通配置（不含密钥）和当前选中配置持久化于本机 `data/model-configs.json`，该路径被 Git 忽略；保存时验证字段并原子替换文件，单 Node 进程使用。删除当前配置后，明确选择剩余配置或显示未选择状态。
- 密钥只通过运行时环境变量提供，例如 `SLIDEAGENT_API_KEY_WORK`。网页保存的是 `WORK` 别名；服务端只解析 `SLIDEAGENT_API_KEY_` 前缀加大写字母、数字、下划线组成的别名，不允许 UI 指向任意环境变量。`.env.local` 不提交，不在配置文件、API 响应或日志中存储/回显值。
- Base URL 只允许 HTTPS；本机推理服务可显式使用 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]`。拒绝 URL 内嵌凭据、查询参数、片段与不支持的协议。此规则**不等于**公网 SSRF 防护；公开部署前需重新审计重定向、DNS 与内网地址限制。

## 验收与测试

- 本机可新增/切换/删除模型配置，重启后普通配置仍在，密钥必须继续由环境变量提供；缺少密钥时连接测试和生成均明确失败。
- 使用模拟 HTTP 响应离线测试三种协议的请求与响应映射、超时/错误、无效输出和一次重试；无测试依赖真实付费调用。
- 覆盖表单边界、配置持久化和无密钥泄漏、URL/密钥别名校验、页数校验，以及生成后 ZIP 中确实包含所请求页数的可编辑幻灯片。M0 的全部测试保持通过；`pnpm test`、`pnpm lint`、`pnpm build` 通过。若环境已提供可用密钥，可另做人工端到端测试，结果与成本单独报告。

## 非目标

不做注册/登录、公开部署、多用户存储、数据库、模型托管、模型市场、自动研究、PDF/DOCX、图像、预览、Vision QA、自动修复、自然语言编辑、模型自动路由或 MCP。多主题视觉风格和额外布局留给后续阶段。
