# M2 补充：叙事大纲、时间轴与数据重点页

## 目标与已确认的流程

在进入 M3 前补齐原 M2 延期的内容组织能力。本机用户提交主题/材料、受众、目的、页数和风格后，先获得可审阅的大纲：看清开场、论点、材料依据和结论如何串联；确认或修改后才生成可编辑 PPTX。不能把“内容组织”简化为改一段 prompt，也不能为凑页面捏造日期、数值或证据。

用户已选择两阶段方案：① 生成大纲 → 直接编辑每页标题与一句核心观点、调整非封面页顺序、可重新生成大纲；② 确认后按该大纲生成 DeckSpec 和 PPTX。封面固定首位，其他页的排序以用户确认结果为准。正常情况下每阶段至少一次模型调用；重新生成大纲和校验重试可能增加费用，页面在操作前提示。大纲暂存于浏览器内存，刷新后需重新规划；不添加数据库、服务端会话或缓存。

生成后仍按当前流程直接下载；M3 才做“生成后先预览、确认再下载”。网页内直接修改已生成幻灯片的正文/布局、多轮自然语言编辑仍留给后续阶段；PPTX 在 PowerPoint 中保持可编辑。

## 语义边界与两阶段接口

- 新增独立 `Outline` 领域 schema，不把未确认的大纲当作 DeckSpec。每页包含稳定 ID、叙事作用（开场/论点/依据/总结）、标题、核心观点和建议的七种语义页面类型之一；建议为时间轴/数据重点页时还须带原始材料中的依据片段，先经来源校验才能展示。均有严格长度与页数约束，不含坐标或厂商对象。大纲首张只能是封面；目标页数 1–10。短演示文稿按页数收缩叙事骨架，不能强迫每一份材料都有四个角色，缺少证据时不得编造“证据页”。
- 新的同源大纲 API 使用当前本机选中的模型与环境变量密钥，返回严格校验过的大纲和可供 UI 展示的安全状态。重新生成大纲是新的请求；若原始输入/目标页数改变，旧大纲失效，必须重新规划。
- 大纲确认后，生成 API 接受经服务端再次严格校验的已确认大纲及原始输入。模型以该大纲生成 DeckSpec：页数、顺序与用户编辑后的标题必须一致；每页核心观点应保留在该页可编辑文本中，不得因模型改写而静默丢失。无法满足时明确失败；客户端传入的模型配置、风格建议或任何坐标均不可绕开现有校验。服务端仍决定最终风格：手选优先，自动建议无效回退经典蓝。
- 保持原 `POST /api/generate` 无大纲请求的兼容行为和 `/api/demo` 经典五页下载。无大纲的旧流程也必须遵守新页面类型的事实约束。两阶段都复用既有三协议适配器、90 秒单次超时、256 KiB 响应上限、禁止重定向、同模型无效输出最多重试一次以及密钥不回显规则；连接/鉴权错误不重试。

## 新语义页面与事实规则

经用户明确同意，在 DeckSpec/SlideSpec 增加 `timeline` 和 `data_highlight` 两种类型；原五种页面的 schema、Demo 和渲染能力保持兼容。两种新页面都用原生可编辑文字与形状，由 Theme → 确定性 Layout → 现有 Renderer 生成；经典蓝、深色科技、暖色简报三套主题均须有清晰、不过界的排布。`timeline` 含标题、总结观点及 2–5 个按时序排列的 `{date, event, sourceQuote}`；`data_highlight` 含标题、`value`、`label`、总结观点及 `sourceQuote`。`sourceQuote` 是用户原始材料的原文片段，用于来源校验，不把任意出处/模型推测当作原文；页面可见文案沿用 M0 短文本上限，来源片段另设合理上限，不含绝对几何坐标。

仅以用户提交的主题和材料作为日期、数值、事件的事实来源；不联网研究，不把模型常识当作已核实事实。时间轴须有材料中的日期—事件对应关系，数据重点页须有材料中的数值和含义：资料不足时大纲不选这两种页面，使用已有类型组织论点，而不是填充虚构值。服务端须确认每个 `sourceQuote` 是原始输入的原文片段，且页面显示的完整日期或数值出现在该片段中，不能用“10”匹配“110”之类的局部数字冒充来源；缺少可比对依据时拒绝该结果，按无效结构的既有上限重试，仍不合格则给出可操作的安全错误。事件解释、标签与来源的语义一致性仍需用户审阅，不声称已自动完成一般事实核查。若用户在大纲文字中新增事实性日期/数值，确认前即提示先补充原始材料并重新生成大纲；服务端在最终调用模型前再次检查，不能让无来源数字绕过校验。

## 网页交互与失败处理

- 原表单提交改为“生成大纲”；展示含角色、标题、核心观点、建议页面类型的大纲。标题和核心观点可直接编辑，非封面页可用可访问的排序控件调整；可返回修改原始输入、重新生成大纲或确认生成。重新生成会覆盖当前编辑，操作前明确提醒；编辑字段即时限长，提交时服务端再次校验；用户自行调整后的顺序必须在 PPTX 中保留。
- 正在请求、成功、错误继续沿用醒目的现有反馈组件；每次可能收费的操作前说明调用次数。大纲无效、材料不足、模型错误、修改文字超限、排版过密均返回安全、可操作的错误，不产生伪装成 PPTX 的下载。若最终生成失败，浏览器保留已编辑大纲供修改后重试；生成成功才清除或切换状态。
- 本阶段不增加注册/权限、持久化草稿、上传文件、预览、图像/图表、任意拖拽排版、另一个模型调用提供风格、自动研究或多模型路由。

## 验收

- 离线假模型覆盖两阶段成功、可编辑标题与核心观点、顺序调整后严格保留、重新生成大纲费用提示、第一页固定、1–10 页叙事收缩、坏 JSON/结构至多一次同模型重试、鉴权/网络错误不重试、旧 API 和 Demo 保持可用；测试绝不使用真实付费密钥。
- 无事实材料时不产生时间轴/数据重点页；有材料时两种新页的日期/数值可回溯，模型凭空增加的数字被拒绝；所有七种页面在三套风格下均能导出正确页数、可编辑文本和形状，文本过密明确报错而非截断。
- `pnpm test && pnpm lint && pnpm build` 在功能分支通过，并以本机拦截模型响应的浏览器测试验证确认/编辑/排序/下载。旧 M2 的三风格 PPTX 尚缺人工逐页打开验收，以及根工作区 `pnpm lint` 误扫 `.worktrees/` 的问题均单列为工程遗留；此功能的测试不能代替这两项收尾，也不在此规格中偷偷扩大为 M3。

## 交付边界

当前只写规格，待用户审阅批准后再另写实施计划并选择执行方式；实现须使用独立功能分支、PR，未经用户确认不合并 `main`。M3 仍按已选方案 A 独立设计：先预览再确认下载；生成后多轮自然语言编辑维持在后续阶段。
