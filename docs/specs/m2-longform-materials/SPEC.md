# M2 后续第一交付：长材料与详细演示文稿

## 目的、依赖与交付顺序

让本机单用户以粘贴的长材料制作最多 100 页、每页有适当解释和例子的**可编辑** PPTX；短文稿仍轻量、长文稿分批，材料不足时不捏造或重复内容凑页。用户先审阅、编辑叙事大纲，再确认生成。此功能依赖 M2 内容大纲 PR #3；本规格所在独立分支基于该 PR，**不表示批准合并 PR #3 或本分支**。

已确认的交付顺序：① 本规格的材料驱动长文稿；② 独立交付“仅主题→联网研究→可追溯引用”的主题模式（提前原路线图 M6 的研究能力，另写规格）；③ 图片上传；④ M3 的下载前预览。PDF/DOCX 输入仍另行规划；第一交付只支持粘贴文本，不借这次开发添加文档解析、图片、研究、RAG、数据库或第二套 PPTX 渲染器。旧的本机三协议、主题、Demo 和无大纲 API 保持兼容，不直接公开部署。

## 用户体验与页数语义

- 输入为主题、粘贴的原始文本、受众、用途、目标页数（1–100）、风格和“简洁 / 详细”模式；默认仍为 5 页、简洁。材料模式必须有非空原始文本；仅有主题的现有短稿入口保持兼容，联网主题模式在第二交付实现。
- “目标页数”是规划目标，不是保证凑满的配额。材料不足时给出可支持的较少页数及原因，让用户明确接受或补充材料，不静默减少页数；模型重复同一观点凑页属于无效结果。封面始终第一页，最终总页数（含叙事插页、排版续页）最多 100 页。
- 详细模式在适合的内容页呈现多条有信息量的解释、必要时有明确标注的例子；封面、数据重点等仍按语义保持简明。不设机械最低字数，也不把正文塞满以牺牲可读性。新长文稿流程的正文优先使用不低于 16pt 的可读字体；内容放不下时拆页，绝不截断或挤成过小文字。
- 模型可在两张原页之间**按叙事逻辑插入相关的解释、例子或过渡页**，但此类叙事页须先出现在可编辑大纲中，用户确认后才进入最终生成。模型生成正文后才发现版面过密时，可自动在对应页后拆出紧邻的“续页”；确认大纲的原页相对顺序、原标题与核心观点必须保留。生成前提示可能出现续页和 100 页硬上限，完成后展示实际页数和新增续页数。
- 大纲与最终文本仍是可编辑语义内容，布局只由确定性程序决定。大纲允许用户编辑标题/观点、移动非封面页、重新规划；已确认的大纲作为原页锚点，生成模型不得偷换它们。若会超过 100 页或不能无损拆页，安全失败，保留已完成工作，不下载不完整的 PPTX。
- 详细、长篇可能需要多次模型调用；在开始规划和确认生成前展示预计批次数/调用次数范围，明确每批无效输出至多同模型重试一次会增加费用；没有模型报价时不虚报金额。

## 分段规划、生成与校验

- 新的长文稿请求最多接受 **200,000 个 UTF-16 字符**的原始文本，且 JSON 请求体上限 **1 MiB**；超限在调用模型前报错。保留原有无大纲 `/api/generate` 和 `/api/outline` 的 1–10 页、20,000 字符边界；扩容走独立的长文稿 API/严格输入 schema，不让旧请求行为发生意外变化。上限不等于每次都把全部材料传给模型。
- 页数 1–10、材料在现有安全预算内、选择简洁模式时沿用现有两阶段轻量流程；详细模式或超过轻量预算的材料/页数走分批流程。两种流程共享 Outline/DeckSpec 语义校验、三协议模型适配、Theme/Layout/Renderer，不引入 AI 坐标。
- 长材料按自然段/标题切片，无法自然分段时按有界长度拆分；每次模型调用仅接收所需片段、全篇阶段性摘要和邻接的叙事上下文。先从材料片段归纳，必要时分层汇总为全篇故事线，再分批规划有稳定 ID 的大纲页；最终按用户确认后的页序分批生成，**每批最多 8 张原页**，最后一次性校验并渲染最多 100 张 PPTX 页。不得把 100 页或 200,000 字材料塞进一次请求。
- 每张来自材料的事实页仍须带原始片段；服务端以**用户原文**校验 `sourceQuote`、完整日期与数值（不能用 `10` 匹配 `110`）。长文稿生成路径对正文新增的显式日期/数值也要求有原文依据；不得把摘要或模型知识当原始证据。例子若非材料事实必须明确标记为假设/示例；无法自动验证事件解释与数值含义的语义真伪，用户仍需审阅。缺材料时拒绝事实页，不联网补造。
- 大纲扩容至最多 100 页；DeckSpec 原七种语义布局不新增新类型，只将 `deckSchema.slides` 上限从 30 调至 100。详细模式优先利用现有多要点、卡片、对比、流程等可编辑文本结构并调整布局空间；排版容量不足时按语义边界拆为续页，而非截字符串。最终页面用内部“原大纲 ID / 续页序号”映射校验锚点和顺序，映射不写入 DeckSpec 或 PPTX 的坐标模型。即使某批模型输出结构有效，也须先通过已确认标题/观点、页序、来源和确定性排版检查才能纳入完成批次。
- 第一次按批验证；无效模型内容在**该批次**最多重试一次，鉴权、网络、限流等错误不自动重试。任何阶段失败、超出模型上下文或达到 100 页上限均给出安全且可操作的错误，不部分下载、不回显密钥/原文。若正文溢出需续页但超过硬上限，让用户缩短内容或返回大纲减页后重试，明确提示会重新调用模型。单次调用继续受 90 秒和 256 KiB 模型响应限制；不保证每种自定义小上下文模型都支持长文稿。

## 本机断点恢复（不是长期项目库）

- 使用 Node 内置文件 API 在已被 Git 忽略的 `data/longform-jobs/` 存放随机不可猜测 ID 的任务快照：输入、材料片段映射、已编辑/确认大纲、已完成批次、阶段和错误状态；**绝不持久化 API 密钥**。每批成功验证后原子写入检查点；服务重启或页面刷新可继续未完成批次，已完成批次不再收费重跑。浏览器仅保存任务 ID，可恢复后读取本机任务状态。
- 同一任务不允许两个页面同时启动相同的付费批次；恢复时核对任务所属的模型配置 ID、原始输入和大纲版本，避免错用旧批次。正在进行的一次调用若遇刷新/进程中断，其费用无法保证避免重复；界面必须说明此边界。短文稿不强制落盘。
- 用户可显式删除任务及本机快照；任务按**最后活动时间 7 天**过期清理（包括已生成完但尚未手动删除的任务）；服务启动和处理任务请求时清理过期快照，不引入独立定时服务。界面提供任务阶段与已完成/总批次的数字进度、取消/失败后继续，不承诺本阶段完整的制作过程可视化、历史项目管理或长期二次编辑。快照中的原始材料可能敏感：不进入 Git、日志、公开响应或浏览器持久存储；只供本机访问，路径和任务 ID 必须严校验。不可直接公开部署无登录版本。

## 测试、验收和失败边界

- 不使用真实付费模型；离线假模型覆盖 1/10/30/100 页、目标不足时明确接受较少页数、101 页拒绝、简洁短稿兼容、长材料分块、三协议、手选/自动风格与旧 Demo。
- 覆盖大纲中叙事插页在两张原页之间、非封面重排、标题/观点锚点保留；布局续页在原页后出现、不能截字/缩成难读字体，最终总页数含续页不得超过 100。检查 100 页 PPTX 页数和 OOXML 可编辑文本/原生形状，三主题布局边界及过密安全失败。
- 覆盖无来源日期/数值、原文片段边界、内容无效单批最多一次重试、401/429/网络不自动重试、失败无部分下载；已完成批次不会因后续批失败被重复调用。
- 覆盖刷新/服务重启后恢复、重复点击与并发锁、原子快照损坏或缺失的安全提示、7 天过期/手动删除、密钥不落盘及原文不进入日志/错误响应、API 的本机同源/请求体大小防护。大纲/材料改变导致旧批次失效时明确警告，不能复用失配结果。
- 每项测试先行；功能分支运行 `pnpm test && pnpm lint && pnpm build`，本机离线浏览器验收分批进度/恢复/下载；人工抽查长文稿 PPTX 的多页密集排版。完成后独立推送并开面向 `main` 的 PR；需先确认其依赖的 PR #3 已合并，绝不自行合并任何 PR。M3 预览仍单独设计，旧 M2 PPTX 人工视觉检查已由用户完成。
